# Community detection для улучшения товарных эмбеддингов

Исследовательская курсовая работа о том, можно ли использовать внутреннюю структуру пространства товарных эмбеддингов как дополнительный сигнал для дообучения модели.

Проект проходит путь от проверки исходных данных и кластеризации до воспроизводимого эксперимента DeepCluster с независимой KNN-оценкой. Главный результат сформулирован честно: в выбранной конфигурации DeepCluster уменьшил loss по кластерным псевдометкам, но **не улучшил** категориальную KNN-метрику относительно исходного encoder. Это показывает, почему одного внутреннего loss недостаточно для оценки качества embeddings.

## Цель и гипотеза

В товарном каталоге одинаковые предложения могут отличаться формулировкой названия, характеристиками и данными продавца. Для matching текст карточки преобразуется в embedding - числовой вектор. Хорошее embedding-пространство располагает одинаковые и близкие товары рядом, а разные - далеко.

**Гипотеза:** локальные сообщества в уже существующем пространстве embeddings можно выделить кластеризацией и использовать номера кластеров как псевдометки для дополнительного обучения encoder.

**Цель:** исследовать структуру пространства товарных embeddings и проверить, улучшает ли дообучение по сообществам представления товаров.

## Данные и модель

Используется parquet-датасет электроники Яндекс Маркета размером около **4,79 млн строк** и **122 категорий**. Для каждого товара доступны:

- `model_text` - текст карточки;
- `category_id` - идентификатор товарной категории;
- служебные поля каталога;
- предвычисленный embedding размерности **312**.

Текстовый encoder - дообученный на товарных данных `rubert-tiny2`. При извлечении нового представления используется CLS-вектор размерности 312. Сохранённые embeddings применяются для быстрых аналитических экспериментов; текст и checkpoint требуются для DeepCluster-дообучения.

Большие файлы не хранятся в Git. Для воспроизведения нужно подготовить assets:

## Исследование исходного пространства

На выборке **20 000 товаров из всех 122 категорий** проверены размерность, нормы, PCA-проекции и косинусная близость.

- PCA до 128 компонент сохраняет **98,52%** дисперсии.
- Средняя cosine similarity внутри категории: **0,2362**.
- Средняя cosine similarity между категориями: **0,0475**.

Следовательно, исходное пространство уже содержит категориальный сигнал: товары одной категории в среднем расположены ближе. Это не означает, что категория равна товарному matching, но подтверждает целесообразность поиска локальных сообществ.

## Кластеризация

Для кластеризации использовались PCA-признаки с L2-нормировкой. Были сравнены KMeans с разным числом кластеров и HDBSCAN.

| Метод | Настройка | Silhouette | ARI с категориями | NMI с категориями | Вывод |
|---|---:|---:|---:|---:|---|
| KMeans | `K=100` | 0,0654 | 0,2379 | 0,5112 | Каждому товару назначается кластер; подходит для DeepCluster |
| HDBSCAN | автоматическое число кластеров | 0,0249* | 0,0027 | 0,0424 | 62,805% объектов отнесены к шуму; не подходит для псевдометок всех объектов |

\* Silhouette для HDBSCAN рассчитан только по объектам, не отнесённым к шуму.

KMeans выбран для итогового эксперимента, потому что создаёт контролируемое число групп и даёт псевдометку каждому товару. Кластеры не обязаны повторять `category_id`: внутри одной категории могут существовать бренды, типы устройств и иные подгруппы.

## DeepCluster

Метод основан на статье [Deep Clustering for Unsupervised Learning of Visual Features](https://arxiv.org/abs/1807.05520) (Caron et al., 2018). Исходная статья применяет идею к изображениям; в проекте схема адаптирована для текстовых embeddings товаров.

Один внешний цикл DeepCluster:

1. **Извлечение embeddings.** Текущий `rubert-tiny2` строит CLS-векторы по текстам товаров.
2. **Предобработка.** Векторы проходят PCA, whitening и L2-нормировку для устойчивой кластеризации.
3. **KMeans.** Векторы разбиваются на `K` групп; номер группы становится `pseudo-label` товара.
4. **Дообучение.** К encoder добавляется временная линейная classification head. Cross-entropy учит модель предсказывать номер кластера по тексту.
5. **Повтор.** После обновления encoder embeddings и кластеры строятся заново; временная head создаётся заново.

Категории товаров не участвуют в псевдометках и функции потерь. Они применяются только для внешней проверки качества embeddings.

### Почему нужен внешний критерий

Падение pseudo-label loss означает только, что модель научилась предсказывать текущие кластеры. Оно не доказывает улучшение matching и не гарантирует лучшую категориальную структуру. Поэтому после каждой итерации обучается отдельный `KNeighborsClassifier` на train-embeddings и оценивается на validation-embeddings по `category_id`.

- **Accuracy** - доля правильно восстановленных категорий.
- **Macro-F1** - средний F1 по категориям с одинаковым весом каждого класса.
- **KNN, k=5, cosine distance** - внешний тест локальной структуры embedding-пространства.

KNN по категориям - proxy-метрика. Финальная оценка matching должна выполняться на размеченных парах одинаковых и разных товаров с `Recall@K`, `Precision@K`, ROC-AUC, PR-AUC и F1.

## Итоговый эксперимент

Полный эксперимент реализован в `notebooks/08_deepcluster_training.ipynb`.

| Параметр | Значение |
|---|---:|
| Категории | 20 |
| Объекты на категорию | 1 250 |
| Train / validation | 20 000 / 5 000 |
| Доля validation | 20% |
| Число кластеров KMeans | 100 |
| PCA-компоненты | 128 |
| Внешние итерации DeepCluster | 3 |
| Batch size | 32 |
| Максимальная длина текста | 128 токенов |
| Learning rate encoder / head | `1e-5` / `1e-3` |
| KNN | 5 соседей, cosine distance |
| Seed | 42 |

Выборка ограничена ресурсами локального Mac. Полный пересчёт текстовых embeddings для миллионов строк требует существенно больше времени и памяти; 25 000 товаров дают достаточно крупную и сбалансированную постановку для сравнения с baseline.

## Результаты

### Внешняя KNN-оценка

| Состояние embeddings | Accuracy | Macro-F1 |
|---|---:|---:|
| Исходный encoder, baseline | **0,8550** | **0,8529** |
| После итерации DeepCluster 1 | 0,8494 | 0,8468 |
| После итерации DeepCluster 2 | 0,8488 | 0,8460 |
| После итерации DeepCluster 3 | 0,8390 | 0,8363 |

К третьей итерации относительно baseline accuracy изменилась на **-1,60 п.п.**, а macro-F1 - на **-1,66 п.п.**.

### Внутреннее обучение по псевдометкам

| Итерация | Loss до обучения | Loss после обучения |
|---:|---:|---:|
| 1 | 4,7369 | 0,2579 |
| 2 | 4,7582 | 0,1902 |
| 3 | 4,7496 | 0,1237 |

Псевдо-loss устойчиво снижается, а параметры encoder действительно меняются: L2-изменение весов последнего attention-слоя составило **0,314391**. NMI соседних кластерных разбиений достигла **0,8650**, то есть разбиения становились стабильнее. NMI кластеров с категориями изменилась с **0,4615** до **0,4576**.

## Вывод

Реализованный pipeline действительно выполняет DeepCluster: embeddings кластеризуются, номера кластеров используются как псевдометки, encoder обновляется, затем embeddings пересчитываются. Внутренняя цель оптимизируется успешно.

Однако в этой конфигурации обучение усилило структуру, найденную KMeans, но не улучшило категориальную KNN-метрику. Корректный вывод:

> DeepCluster реализован и проверен на независимом train/validation-разбиении. В выбранной конфигурации снижение loss по псевдометкам не перенеслось в улучшение категориальной proxy-метрики.

Это содержательный отрицательный результат: он показывает необходимость независимой оценки и не позволяет утверждать улучшение matching только по уменьшающемуся loss.

## Ход работы

Работа построена как последовательное исследование. Каждый этап отвечает на отдельный вопрос и создаёт основу для следующего, поэтому итоговый эксперимент DeepCluster не является изолированным запуском модели.

1. **Проверка датасета и текстов - `01_eda.ipynb.ipynb`.** Из parquet были считаны структура таблицы, категории, текстовые поля и объём данных. Это позволило определить, какие признаки доступны для анализа, и оценить, почему полный расчёт по нескольким миллионам строк нецелесообразен на локальном Mac.

2. **Проверка формата embeddings - `02_embeddings.ipynb`.** На этом шаге были декодированы и проверены исходные векторы товаров: размерность, корректность значений и возможность использовать их для расчёта расстояний. Цель этапа - убедиться, что дальнейшие PCA и кластеризация работают с корректным числовым представлением товара.

3. **Анализ геометрии пространства - `03_embeddings_visualization.ipynb`.** На расширенной выборке 20 000 товаров были построены PCA-проекции, изучены нормы и расстояния, а также сравнена близость товаров внутри одной категории и между разными категориями. Это подтвердило наличие исходной структуры: категория связана с положением товара в embedding-пространстве, хотя не определяет его полностью.

4. **Поиск сообществ - `04_clustering.ipynb`.** Для тех же 20 000 товаров были применены KMeans и HDBSCAN. Сравнение по Silhouette, ARI и NMI показало, что KMeans лучше подходит именно для задачи создания псевдометок: он назначает кластер каждому объекту. HDBSCAN оказался полезен как диагностический эксперимент, но оставил значительную часть каталога шумом.

5. **Адаптация метода из статьи - `05_article_method.ipynb`.** Был разобран DeepCluster и определено, как перенести его из работы с изображениями на тексты товаров. Основная идея сохранена: encoder создаёт векторы, кластеризация создаёт псевдометки, а encoder дообучается предсказывать эти псевдометки.

6. **Подготовка технического pipeline - `06_deepcluster.ipynb` и `07_deepcluster.ipynb`.** В этих ноутбуках восстановлен encoder из checkpoint, проверена совместимость tokenizer и весов, организовано чтение parquet по row groups и подготовлены `Dataset`/`DataLoader`. Это делает извлечение embeddings и обучение выполнимыми на выборке без загрузки всего датасета в память.

7. **Итоговый эксперимент - `08_deepcluster_training.ipynb`.** Из 20 категорий была сформирована сбалансированная выборка в 25 000 товаров, затем она была разделена на train и validation. Сначала измерен KNN-baseline исходного encoder. После этого проведены три внешние итерации DeepCluster: извлечение embeddings, KMeans с 100 кластерами, обучение encoder на псевдометках и повторная внешняя KNN-проверка.

8. **Интерпретация.** Внутренний loss снижался, то есть encoder всё лучше предсказывал кластеры, созданные KMeans. Но независимая KNN-метрика по категориям снижалась. Поэтому результат работы - не заявление об улучшении matching, а проверенная реализация DeepCluster и экспериментальное доказательство того, что выбранная self-supervised цель требует подбора настроек и проверки на внешней задаче.

Ключевые графики, таблицы и сохранённые результаты находятся в соответствующих ноутбуках. `08_deepcluster_training.ipynb` дополнительно создаёт таблицы метрик, графики, конфигурацию и итоговые веса encoder в `results/08_deepcluster_training/<run_id>/`; этот каталог не предназначен для Git.

## Ограничения и следующие шаги

1. Категориальный KNN - косвенная метрика; нужна оценка на размеченных парах одинаковых товаров.
2. Эксперимент использует 25 000 товаров, а не полный каталог. Масштабирование потребует серверных ресурсов или mini-batch-кластеризации.
3. Число кластеров, learning rate, число итераций и балансировка кластеров требуют систематического подбора.
4. Следует сравнить DeepCluster с contrastive learning и дообучением на положительных/отрицательных товарных парах.
5. Полезно проверить замораживание нижних слоёв encoder, раннюю остановку и несколько random seed.
